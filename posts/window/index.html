一、概念

Flink 是一个流处理框架，而流数据本质上是无界的，但是又经常需要执行一些有界的计算，如统计过去 5 分钟网站的点击量。窗口可以将流切分成有限大小的多个“存储桶”（bucket），每条数据会分发到对应的桶中，当到达窗口结束时间时，就对每个桶中收集的数据进行计算处理。

注：窗口并不是静态准备好的，而是动态创建的，即当有落在这个窗口区间范围的数据到达时，才创建对应的窗口。

二、分类

2.1 按处理的数据流的类型划分

2.1.1 KeyedWindow

用于处理按 Key 分片之后的数据流，即需要先执行 keyBy，再调用 window 方法。

2.1.2 Non-Keyed Window / All Window

用于处理未按 Key 分片的数据流，在使用时直接调用 windowAll 方法。

2.2 按照驱动类型分

2.2.1 时间窗口（Time Window）

以时间点定义窗口的开始和结束（左闭右开区间），因此截取的是某一时间段的数据。到达结束时间时，触发窗口计算。

2.2.2 计数窗口（Count Window）

基于元素的个数截取数据，到达固定的个数时触发计算。每个窗口截取数据的个数就是窗口的大小。

需要传入一个长整型的参数 size，表示窗口的大小。

需要传入两个参数，size 和 slide，前者表示窗口的大小，后者表示滑动步长。

2.3 按窗口分配数据的规则分类

2.3.1 滚动窗口

有固定的大小，是一种对数据进行“均匀切片”的划分方式。窗口之间没有重叠，也不会有间隔，是“首尾相接”的状态。最简单的窗口形式，每个数据都会被分配到一个窗口，而且只会属于一个窗口。滚动窗口可以基于时间定义，也可以基于数据个数定义。适用于对每个时间段做聚合统计。

.of 方法传入一个 Time 类型的参数 size，表示滚动窗口的大小。也可以传入两个参数，即 size 和 offset，分别表示窗口的大小和窗口起始点的偏移量。

2.3.2 滑动窗口

有固定的大小，但是窗口之间并不是首尾相接，而是可错开一定的位置。当滑动步长小于窗口大小时，滑动窗口会出现重叠。数据可能被同时分配到多个窗口中。适用于计算结果更新频率高的场景。

.of() 方法需要传入两个 Time 类型的参数，size 和 slide，前者表示滑动窗口的大小，后者表示滑动步长，也可以追加第三个参数，用于指定滑动窗口的起始偏移量。

2.3.3 会话窗口

基于会话对数据进行分组，只能基于时间定义。最重要的参数是会话的超时时间（两个会话窗口之间的最小距离）。如果相邻两条数据的时间间隔（gap）小于等于指定的大小（size），说明会话保持，数据属于同一个窗口；如果 gap 大于 size，则新到达的数据应属于新的会话窗口。会话窗口的长度不固定，起始和结束时间也不确定，各个分区之间窗口没有任何关联。会话窗口一定不会重叠。

窗口分配器由类 ProcessingTimeSessionWindows 或 EventTimeSessionWindows 提供，需要调用其静态方法 .withGap 或 .withDynamicGap()，传入一个 Time 类型的参数 size，表示会话的超时时间，即两个会话之间的最小间隔。

2.3.4 全局窗口

窗口全局有效，会将相同 key 的所有数据都分配到同一个窗口中，没有结束的时间且默认不会触发计算，如果需要对数据进行计算，则需要显式配置其他触发器（Trigger）。适用于需要做更加灵活的窗口处理时自定义使用。计数窗口底层使用全局窗口实现。

三、窗口函数

窗口函数定义了要对窗口中收集的数据执行的计算操作。根据处理的方式可以分为两类，增量聚合函数和全窗口函数。

3.1 增量聚合函数

每到一条数据就在之前结果上聚合一次，窗口状态中不保存原始数据。包括

3.1.1 ReduceFunction

聚合状态的类型、输出结果的类型都必须和输入数据的类型一致。核心方法是

适用于求和、求最大值、最小值、合并同类型对象等场景。

3.1.2 AggregateFunction

包含三种类型，分别是输入数据的类型（IN）、累加器类型（ACC，进行聚合的中间状态类型）、输出数据类型（OUT）。包含四个方法

  • createAccumulator：创建一个累加器，为聚合创建一个中间状态，每个聚合任务只会调用一次。
  • add：将输入的元素添加到累加器中。
  • getResult：从累加器中提取聚合的输出结果。
  • merge：合并两个累加器，并将合并后的状态作为一个累加器返回。

工作原理是，首先调用 createAccumulator 为任务初始化一个状态（累加器），而后每来一个数据就调用一次 add 方法，对数据进行聚合，得到的结果保存在状态中，当窗口需要输出时，再调用 getResult 方法得到计算结果。由于输入、中间状态、输出的类型可以不同，因此更加灵活。

3.2 全量窗口函数

基于全部的数据进行计算，输出结果中能够包含上下文的相关信息，如窗口的起始时间。全窗口函数会先收集窗口中的数据，并缓存在 WindowOperator 的 ListState 中，等到窗口需要输出结果时再进行计算。分为两类

3.2.1 ProcessWindowFunction

Window API 中最底层的通用窗口函数抽象类，不仅可以拿到窗口中的所有数据，还可以获取到一个上下文对象（Context），可以通过其获取窗口信息，还可以访问当前的时间（包括处理时间和事件时间水位线）和状态信息，适用于需要窗口元数据的场景。

注：WindowFunction 作用可被 ProcessWindowFunction 全覆盖，因此已经被弃用。

增量聚合和全量窗口函数的结合使用：调用 WindowedStream 的 .reduce() 和 .aggregate() 方法时，可以传入第二个参数，一个是全窗口函数。

这样调用的处理机制是，基于第一个参数（增量聚合函数）处理窗口数据，每来一个数据就做一次聚合；等到窗口需要触发计算时，调用第二个参数（全量窗口函数）处理逻辑输出结果。这里的全量窗口函数不再缓存所有数据，而是直接将增量聚合函数的结果作为 Iterable 类型的输入。能够结合两者的优点

  • 增量聚合：来一条数据计算一条，存储中间的计算结果，占用的空间少。
  • 全窗口函数：可以通过上下文实现灵活的功能。

四、KeyedWindow

4.1 WindowAssigner

对 KeyedStream 调用 window 方法会转换成 WindowedStream，该方法需要传入一个 WindowAssigner，它用来确定一条消息属于哪几个窗口，它不保存元素、不决定何时计算、不执行窗口函数。它有四个核心方法

  1. assignWindows 方法：根据元素、时间戳和当前处理时间，返回元素所属窗口的集合。
  2. getDefaultTrigger 方法：默认触发器，事件时间滚动/滑动窗口默认使用 EventTimeTrigger，处理时间窗口默认使用 ProcessingTimeTrigger，可以调用 .trigger() 覆盖默认值。
  3. getWindowSerializer 方法：提供窗口对象的序列化器，使 Flink 能够将窗口作为状态和定时器的 namespace，并将包含该 namespace 的状态和定时器写入 Checkpoint，并在故障后恢复。
  4. isEventTime 方法：声明窗口的时间语义。

在 TumblingEventTimeWindows 中，根据消息的 timestamp 确定窗口的开始和结束时间，然后返回消息所属的窗口。

将定义好的 WindowAssigner 传入 window 方法后，会创建一个 WindowOperatorBuilder，它负责创建一个 WindowOperator 对象，其用于执行窗口具体的计算逻辑。

五、触发器

决定何时触发窗口计算，每一个 WindowAssigner 都有一个默认的 Trigger，也可以通过调用 WindowedStream 的 .trigger() 方法，传入一个继承 Trigger 抽象类的自定义窗口触发器。

该接口提供了五个方法，分别是

  1. onElement：在接收到元素时调用，对元素进行处理；
  2. onProcessingTime：在一个基于 ProcessingTime 的 Timer 触发时调用；
  3. onEventTime：在一个基于 EventTime 的 Timer 触发时调用；
  4. onMerge：在多个窗口合并时调用；
  5. clear：在清除窗口状态数据时调用。

前三个方法都会返回一个 TriggerResult，其值决定了是否触发窗口计算

  1. CONTINUE：什么都不做；
  2. FIRE_AND_PURGE：触发计算并清空窗口内的元素；
  3. FIRE：只触发计算，不清空窗口内的元素；
  4. PURGE：清空窗口内的元素，不触发计算。

Flink 中内置了多个 Trigger，包括 EventTimeTrigger、ProcessingTimeTrigger、CountTrigger 和 PurgingTrigger。

六、移除器

可以用于 Trigger 触发后、调用窗口函数之前或者之后删除窗口内的元素。通过调用 WindowedStream 的 .evictor() 方法，可以传入一个实现 Evictor 接口的自定义移除器，该接口提供了以下方法

  1. evictBefore：在调用窗口函数之前调用；
  2. evictAfter：在调用窗口函数之后调用。

Flink 内置了三种 Evictor，分别是

  1. CountEvictor：记录用户设置的最大元素数量，当窗口内元素数量大于最大元素数量时，删除开头的元素。
  2. DeltaEvictor：用户需要设置计算差值的方法，Evictor 会计算最后一个元素与窗口内每个元素的差值，并将大于等于用户设置的 threshold 的元素删除。
  3. TimeEvictor：用户需要指定窗口大小 windowSize，Evictor 会计算窗口内元素最大的时间戳 maxTimestamp，将时间戳小于等于 maxTimestamp - windowSize 的元素清除。

如果设置了 Evictor，WindowOperatorBuilder 会创建 EvictingWindowOperator。在执行窗口计算逻辑前后，都会调用 evictBefore 和 evictAfter。

七、WindowOperator

设置好 WindowOperatorBuilder 之后，可以调用 process、reduce 等方法指定窗口计算逻辑

WindowedStream 的 process 方法通过调用 WindowOperatorBuilder 的 process 方法生成 WindowOperator，再将 WindowOperator 包装为 Transformation 并注册到执行环境。

7.1 processElement 方法

WindowOperator.processElement() 方法负责处理一条进入窗口算子的消息，它完成四件事情，包括确认当前 Key → 为消息分配窗口 → 将消息写入对应的窗口状态 → 调用 Trigger 判断是否计算、输出或清空窗口。

key 的主要作用包括

  1. 决定消息发送给哪个并行子任务：相同 key 一定进入同一个并行子任务，不同 key，可能进入不同子任务。
  2. 隔离窗口状态：即使窗口时间范围相同，不同的 key 的状态也完全隔离。
  3. 窗口触发后传给用户窗口函数。

window 的主要作用包括

  1. 作为窗口的 namespace：Keyed State 的完整逻辑位置是「状态名称 + key + window namespace」。
  2. 作为定时器的 namespace：一个窗口定时器可以理解为「key + window + timestamp + timer type」。
  3. 提供窗口结束时间
  4. 传给用户窗口函数，使用户能够获得窗口边界。

事件时间窗口的三个时间点：逻辑结束时间、首次触发时间、最终清理时间。假设窗口为 [10:00:00.000, 10:05:00.000)，则窗口的逻辑结束时间是 10:05:00.000，窗口内最大时间戳 maxTimestamp = end - 1 ms；使用默认的 EventTimeTrigger 时，在 maxTimestamp 注册事件时间定时器，因此当 Watermark 到达或超过 maxTimestamp 时，窗口首次触发计算；最终清理时间为 cleanupTime = maxTimestamp + allowedLateness，当 allowedLateness = 0 时，窗口首次触发后立即清理，当 allowedLateness > 0 时，状态会保留到清理时间，在此期间允许迟到数据更新窗口并可能再次触发输出。
