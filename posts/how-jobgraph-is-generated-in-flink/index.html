Flink 中的 JobGraph 是如何生成的？
Shen Huanglin
  2026 年 04 月 21 日   2026 年 04 月 23 日
  • Flink

一、StreamGraph 和 JobGraph 的区别

StreamGraph 是 Flink 客户端根据 Transformation 列表生成的图，它最直接地反映了 DataStream API 中编写的逻辑，而 JobGraph 则是对 StreamGraph 进行算子链合并优化后的结果。

StreamGraph JobGraph
位置 客户端 客户端
层级 逻辑层 优化层
节点 StreamNode JobVertex
边 StreamEdge JobEdge
优化 无 算子链优化

采用多层转换的原因：

  1. 降低耦合：StreamGraph 负责管理表达逻辑，JobGraph 负责管理优化性能，使 Flink 能够在不改变用户代码的情况下，不断升级底层优化算法。
  2. 减少开销：若直接按照 StreamGraph 执行，则每个算子都会产生一个 Task 线程，在大规模集群下，过多的线程竞争和网络 Shuffle 会直接拖垮性能，JobGraph 通过 JobVertex 降低任务的物理复杂度。
  3. 确定资源：JobGraph 生成后，Flink 可以确定需要的 Slot 的数量。

二、StreamGraph 转换成 JobGraph

StreamGraph 转换成 JobGraph 的入口是 StreamGraph 类的 getJobGraph 方法，其调用了 StreamingJobGraphGenerator 的 createJobGraph 方法

其中最核心的步骤是调用了 setChaining 方法，在其中遍历了 StreamGraph，将能够 Chain 在一起的算子合并成一个 JobVertex（在同一个 Task 中执行），从而减少线程切换和数据序列化开销

算子链的入口通过 buildChainedInputsAndGetHeadInputs 方法确定

创建算子链是通过 createChain 方法

创建链的递归结束后，会返回到链的起始节点，就会通过 createJobVertex 方法将每个链转换为 JobGraph 中的 JobVertex

构建算子链完成后，通过 setAllVertexNonChainedOutputsConfigs 方法创建 JobEdge

该方法遍历了 jobVertices，这是一个以算子链的入口节点 ID 为 key，以对应的 JobVertex 为 value 的 map，并逐一调用了 setVertexNonChainedOutputsConfig 方法

在该方法中对当前算子链的每一条输出边调用了 connect 方法，从而在当前 JobVertex 的 IntermediateDataSet 和下游 JobVertex 之间建立 JobEdge

关于 JobEdge 是建立在上游 JobVertex 的 IntermediateDataSet 和下游 JobVertex 之间这一点，可在创建 JobEdge 时调用的 connectNewDataSetAsInput 方法中得到验证

三、JobVertex

JobGraph 主要是由 JobVertex 和 JobEdge 构成，因此对它们的主要成员变量进行了梳理和解释。

JobVertex 是 JobGraph 中的节点，代表一个可并行执行的任务单元，可能包含多个算子，其包含以下成员变量

3.1 拓扑结构

3.2 执行配置

3.3 调度约束

3.4 状态标志

四、JobEdge

JobEdge 是 JobGraph 中的边，连接上游 JobVertex 的 IntermediateDataSet（中间数据集）和下游的 JobVertex（消费者顶点）。JobEdge 的方向是 IntermediateDataSet → JobVertex，而不是 JobVertex → JobVertex。一个 JobVertex 可以有多个 JobEdge 作为输入，每条边对应一个 InputGate。其具有以下成员变量

4.1 拓扑结构

4.2 数据传输配置
