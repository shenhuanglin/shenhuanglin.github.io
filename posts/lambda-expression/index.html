Java 特性：Lambda 表达式
Shen Huanglin
  2025 年 11 月 04 日   2026 年 04 月 23 日
  • Java

一、概述

Lambda 表达式是 Java 8 引入的最重要的特性之一。它本质上是一个匿名函数，即没有名称、不属于任何类的函数，它可以传递到代码中作为参数，使代码更加简洁、灵活。核心思想是将代码参数化。

二、作用

Lambda 表达式主要用于解决匿名内部类的冗余。在 Lambda 表达式出现之前，想要传递一个行为，通常需要使用匿名内部类，例如创建一个线程并执行

三、语法

Lambda 表达式由三部分组成

  1. 参数列表：与方法参数列表一致，参数类型可以省略（编译器会自动推断，但是更推荐显示指定，能够避免类型擦除问题）。如果只有一个参数，() 也可以省略。
  2. 箭头符号：将参数列表和表达式主体分离。
  3. 表达式主体：
    • 单个表达式：只有一行代码，可以省略 {}，并且表达式的值会自动作为返回值。
    • 代码块：多行代码，需要使用 {}，如果需要返回值，需要显式使用 return 语句。

四、函数式接口

函数式接口是指只有一个抽象方法的接口（可以有多个 default 和 static 方法），通常使用 @FunctionalInterface 注解进行标识（不强制要求）。

注：① 接口中的方法默认是 public abstract 的，因此通常会省略这两个关键字。

② 在 Java 中，所有类都直接或间接继承 Object 类，计算某个接口的抽象方法个数时，从 Object 类继承的公共抽象方法不参与计数。例如在 Comparator<T> 接口中，声明了两个抽象方法，compare 方法和 equals 方法，但是 equals 方法是从 Object 类的，因此 Comparator<T> 接口仍属于函数式接口。

Java 内置了四个核心的函数式接口

  1. Consumer<T>：消费型接口，包含一个 void accept(T t) 抽象方法，对 T 类型的对象进行操作，消费数据。
  2. Supplier<T>：供给型接口，包含一个 T get() 方法，产生 T 类型的对象并返回。
  3. Function<T, R>：函数型接口，包含一个 R apply(T t) 方法，对 T 类型的对象进行操作，返回 R 类型的结果。
  4. Predicate<T>：断言型接口，包含一个 boolean test(T t) 方法，判断 T 类型的对象是否满足指定条件。

Lambda 表达式只能用于替代函数式接口的抽象方法的实现，因为 Lambda 表达式本身是一个匿名函数，没有固定的类型，需要从一个目标类型的上下文中被推断出来，所以只有函数式接口的唯一的、没有实现的抽象方法的类型能够被明确推断出。

注：Lambda 表达式是实现，不是重写。Lambda 表达式是作为函数式接口的唯一抽象方法的实现，不能用于覆盖接口中已经实现的方法，如 default 方法或 Object 类中的方法。

六、与匿名内部类的区别

  1. 语法层面：Lambda 表达式更加简洁。
  2. 实现原理：匿名内部类编译后会产生一个新的类文件；Lambda 表达式在编译后不会生成新的类文件，它使用 invokedynamic 指令在运行时动态生成实现类（隐藏在 JVM 内部），性能更高。
  3. 作用域：匿名内部类中的 this 指向匿名内部类自身的实例；Lambda 表达式中的 this 指向包围它的外部类的实例。

七、变量捕获

变量捕获是指 Lambda 表达式可以访问其外部作用域中定义的变量。但是要求被捕获的变量必须是 final 或者等效于 final，即变量在初始化后，其值不再被改变。

原因：Lambda 表达式可能放在一个新的线程中运行，而局部变量存储在线程的栈帧中，为保证数据一致性，Java 采用值拷贝策略，若变量可变，会导致数据不同步。
